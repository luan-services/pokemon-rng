# Testing

## Automated

Compile sources plus the test runner:

```cmd
javac -encoding UTF-8 -d out src\*.java tests\TestRunner.java
java -cp out TestRunner
```

The tests verify:

- seed bounds;
- `0x1234` predecessor and first state;
- RamScript size/checksum;
- ROM/effect catalog;
- fixed runtime-region layout;
- **byte-for-byte equality** with the known-good `0x1234` golden payload;
- SHA-256 of the golden payload.

Golden reference:

```text
testdata/seed-hotkey-fr10-1234.golden.bin
size    1004
SHA256  7a4d45dddb10288af7cd7eef6bdeec2d578c3f516f08e791f1fcf519279cab0d
```

If the generated bytes differ, the test fails even if the Java code compiles.

## Manual known-good validation

The fixed-RAM seed modifier has already been manually exercised through:

```text
map transitions
Pokémon Center stairs
entering/leaving buildings
Party/menus
battles
healing
NPC interactions
repeated R+SELECT activation
```

The older SaveBlock/relocating-hook candidates crashed intermittently during
transitions. The current fixed-RAM architecture did not reproduce those crashes
during the validation session.

## RNG validation

For seed `0x1234`, manual RAM observation showed the expected RNG sequence.

A practical Pokémon-generation test also produced a PID present in the expected
frame list; it was observed at frame 32 during that test.

This is recorded as an empirical integration result, not encoded as an
automated Pokémon-generation test.

## Release rule

A Java-only cleanup may be accepted without another emulator run only when:

```text
golden bytes are identical
```

Any intentional machine-code/output change is a **new native candidate** and
must be manually tested again before replacing the known-good implementation.
