# wc3-builder

Java 21 command-line tool for inspecting, creating, and editing the **Wonder Card details/design** of Pokémon FireRed/LeafGreen `.wc3` files.

Its responsibility is intentionally limited:

```text
wc3-builder
= card details / text / appearance / metadata

ramscript-tools
= normal Field Script behavior

native-ramscript-tools
= native Thumb/ARM payloads
```

The only exception is the built-in placeholder RamScript attached by `create`, so a card created from zero is immediately usable. It is not exposed as a general RamScript editor.


## Machine-facing JSON API v1

The JavaFX desktop application should use the JSON API instead of parsing human CLI output:

```powershell
java -jar wc3-builder-api-v1.jar api version
java -jar wc3-builder-api-v1.jar api catalog
java -jar wc3-builder-api-v1.jar api inspect --input event.wc3
java -jar wc3-builder-api-v1.jar api create --output custom.wc3 --title "MY EVENT" --flag 1003
java -jar wc3-builder-api-v1.jar api edit --input event.wc3 --output custom.wc3 --bg 5
```

Protocol: `wc3-builder-json`, API version `1`. See `docs/API_V1.md`.

### Wonder Card receive slots

`--flag` is modeled as the FR/LG Wonder Card **receive ID**, not as an arbitrary event flag. The supported UI/API range is `1000..1019`: Aurora Ticket, Mystic Ticket, the Old Sea Map reserved slot, and 17 dedicated unused Wonder Card slots. General unused event flags remain the responsibility of the event/RamScript layer. See `docs/WONDER_CARD_FLAG_SEMANTICS.md`.

## Compile

```cmd
javac -encoding UTF-8 -d out src\*.java
```

## Inspect

```cmd
java -cp out Main inspect event.wc3
```

The inspector prints:

- card CRC;
- RamScript checksum status;
- flag ID;
- icon species and mirrored metadata icon;
- card ID;
- type;
- background;
- send type;
- max stamps;
- title/subtitle;
- four body lines;
- two footer lines.

## Create a card from zero

```cmd
java -cp out Main create custom.wc3
```

This creates a complete `0x58C`-byte WC3 with:

```text
flagId       1003
iconSpecies  0xFFFF
idNumber     0
type         GIFT
background   0
sendType     DISALLOWED
maxStamps    0
```

and a basic editable design.

The deliveryman has a harmless built-in placeholder event:

```text
This custom card was generated by
Choppy's wc3 builder.

It has no event attached.
```

Internally the text uses Gen III line/page control codes, but the visible wording is the same.

The placeholder:

- does not give an item;
- does not give a Pokémon;
- does not set/clear flags;
- does not modify the save;
- only shows the informational message.

To attach a real event later, replace the RamScript with `ramscript-tools` or `native-ramscript-tools`.

### Create with custom details immediately

The same options accepted by `edit` are accepted by `create`:

```cmd
java -cp out Main create custom.wc3 --title "MY CUSTOM EVENT" --subtitle "CHOPPY TEST" --icon 25 --bg 5```

## Edit an existing card

```cmd
java -cp out Main edit input.wc3 output.wc3 --title "PIKACHU TEST" --subtitle "JAVA WC3 BUILDER" --body1 "This card should show" --body2 "a Pikachu icon in the" --body3 "upper-right corner." --body4 "Injection test complete!" --footer1 "Custom Wonder Card" --footer2 "Created with Java" --icon 25 --id 0 --type 0 --bg 5 --send 0 --stamps 0
```

Available options:

```text
--title
--subtitle
--body1
--body2
--body3
--body4
--footer1
--footer2
--flag
--icon
--id
--type
--bg
--send
--stamps
```

Numbers may be decimal or hexadecimal.

## Important behavior

`--icon` is intentionally handled by `Wc3File.setIconSpecies()` instead of directly by `WonderCard`.

This keeps:

```text
WonderCard.iconSpecies
WonderCardMetadata.iconSpecies
```

synchronized, matching the behavior expected by the game/toolchain.

Editing card details recalculates the **card CRC only**. The existing RamScript is preserved byte-for-byte.

`create` is different because there is no existing RamScript to preserve; it generates the one fixed placeholder message described above.

## Scope

This project does not compile arbitrary event scripts.

That remains deliberately separate so card design and event behavior stay distinct concepts.

## Mystery Gift default icon

`iconSpecies = 0xFFFF` is the stock/default Mystery Gift question-mark icon used by preserved FR/LG ticket Wonder Cards. In `api catalog` this is exposed semantically as `MYSTERY_GIFT_DEFAULT` / `Mystery Gift (?)` with `kind = SPECIAL`. It is not `NONE` and it is not Unown ?. `Wc3File.setIconSpecies(...)` mirrors the selected value into both `WonderCard.iconSpecies` and `WonderCardMetadata.iconSpecies`. The JavaFX UI must present the semantic catalog item and send its raw `value` back to the backend.
